# PostgreSQL и pgAdmin: как показать свою работу

Создана отдельная база `gamezone_dev`, владелец `adi`, PostgreSQL 16.16. На ней успешно выполнены 81 миграция и два запуска seed. Проверенные количества после повторного запуска: 54 товара, 18 категорий, 3 SUPERADMIN. Это реальные данные PostgreSQL, не localStorage.

pgAdmin — отдельный клиент управления PostgreSQL. Его использование нужно показать отдельно: наличие Prisma и работающей базы не доказывает работу в pgAdmin. pgAdmin 4 установлен и открыт. Через официальный setup.py добавлено подключение GameZone local в группу GameZone; host localhost, port 5432, database gamezone_dev, user adi. Если список в открытом окне не обновился, обновите дерево серверов.

## Подключение

После установки и открытия pgAdmin добавьте сервер со следующими параметрами:

| Параметр | Значение |
| --- | --- |
| Имя подключения | GameZone local |
| Host | localhost |
| Port | 5432 |
| Maintenance database | gamezone_dev |
| Username | adi |

На этом компьютере подключение psql по localhost прошло без пароля. Не придумывайте пароль; если pgAdmin требует его, проверьте локальные правила аутентификации PostgreSQL. Не показывайте пароли, хэши пользователей и токены на скриншотах.

Откройте базу gamezone_dev, схему public и таблицы. В Query Tool выполните файл [postgres-proof.sql](src/server/scripts/postgres-proof.sql): он показывает версию сервера, пользователей без паролей, категории, товары, характеристики через JOIN и историю миграций.

## Что показать преподавателю

1. Подключение в pgAdmin и результат `SELECT current_database(), version();`.
2. Таблицы Product, ProductVariant, Category, Attribute и User. Объясните: цена и остаток хранятся у варианта товара, а не у общей карточки.
3. JOIN из подготовленного SQL-файла: категория → товар → вариант → характеристики.
4. Записи трёх администраторов с одинаковой ролью SUPERADMIN, без поля password.
5. Миграции в репозитории и соответствующие записи _prisma_migrations.
6. В режиме реального API измените тестовый товар в админке, затем повторите SELECT в pgAdmin. Новое значение должно совпасть. Не используйте NEXT_PUBLIC_DEMO_MODE=true для этого доказательства.

Сделайте свои скриншоты и короткую запись экрана с изменением через приложение и повторным SQL-запросом. Это воспроизводимая демонстрация вашей работы; один скриншот списка таблиц не показывает взаимодействие приложения с БД.

## Локальный запуск

Используйте Node.js 22 (версия записана в .nvmrc). Node.js 26 на этом компьютере вызвал падение старой JWT-зависимости при старте сервера.

```sh
cd src/server
node scripts/dev-local.cjs
```

Скрипт использует существующие переменные окружения, а для пустых значений подставляет локальную базу gamezone_dev, Redis localhost:6379, порт 5001 и временные случайные секреты. .env не переписывается. После перезапуска временные ключи меняются, поэтому потребуется повторный вход. Скрипт предназначен для этого локального окружения, не production.

В другом терминале из корня проекта:

```sh
cd src/client
NEXT_PUBLIC_DEMO_MODE=false NEXT_PUBLIC_USE_DEMO_CATALOG=false NEXT_PUBLIC_API_URL_DEV=http://localhost:5001/api/v1 NEXT_PUBLIC_SOCKET_URL=http://localhost:5001 npm run dev
```

Клиент должен работать на 3000, чтобы совпадать с настройкой CORS. Проверяйте http://localhost:5001/health/detailed. Stripe, OAuth, SMTP и Cloudinary требуют собственных настроек для соответствующих операций; отсутствие ключей не является подтверждением работы этих интеграций.

## Проверено при продолжении работы

Через браузер выполнен вход Санжара, цена GAMEZONE-CARDS-3 изменена 15000 → 15001. SQL подтвердил новую цену и прежний ID варианта; после перезагрузки админка показала 15001. Затем цена восстановлена до 15000. Проверены добавление GAMEZONE-SWITCH-1 в корзину и увеличение количества 1 → 2, подтверждённые SELECT из CartItem. Созданная проверкой позиция удалена через интерфейс.

Теперь API возвращает все 18 категорий вместо первых 16. Фикстуры деморежима не использовались. SQL выполнялся через psql; выполнение Query Tool внутри окна pgAdmin автоматически не проверялось. Для облачной PostgreSQL см. DEPLOYMENT.md.
