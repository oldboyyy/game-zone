# Бесплатный сервер GameZone: Render + Neon

Цель: https://github.com/oldboyyy/game-zone (публичный репозиторий, при проверке пуст).
Локальный remote `game-zone` указывает на него; `origin` оставлен исходным. Код пока не опубликован.

## Что подготовлено

`render.yaml` создаёт Node.js API и Key Value на **free** в Frankfurt. PostgreSQL подключается отдельно из Neon Free. Автоматическое развёртывание выключено. API поддерживает существующий Socket.IO; архитектуру менять не нужно.

Тарифы проверены 19 ноября 2026:
- Render Free: 750 часов на workspace в месяц, сервер засыпает после простоя; пробуждение занимает время. Бесплатный Key Value хранится в памяти и теряет сессии/кэш после перезапуска.
- Neon Free: PostgreSQL без ограничения по времени, в пределах бесплатных квот. Не включать платный план.
- Render Free Postgres не используем: база истекает через 30 дней.

Источники: https://render.com/docs/free, https://neon.com/pricing, https://render.com/docs/websocket.

## Порядок публикации

1. Подключить аккаунты Neon и Render. Создать проект Neon Free в регионе рядом с Frankfurt. Использовать строку PostgreSQL с TLS; для первого запуска и миграций предпочтительно прямое подключение, не pooler. Не публиковать URL базы.
2. Подготовить чистую публикацию в `oldboyyy/game-zone`: исключить `.env*`, логи, `.playwright-mcp`, дампы, node_modules и сборки. В текущем Git уже отслеживаются старые серверные логи — одного `.gitignore` недостаточно. Команда `node scripts/prepare-release.cjs` создаёт в системной временной папке чистый снимок текущих файлов без Git-истории, секретных env, логов и сборок. Для пустого целевого репозитория можно публиковать этот снимок после проверки, не перенося исторические логи. Исходная рабочая папка не изменяется. Сохранить LICENSE и авторство исходного проекта.
3. В Render создать Blueprint из этого репозитория и `render.yaml`. Проверить, что оба сервиса имеют план **Free** и итог $0. Не включать платные опции.
4. Ввести только следующие значения; остальные секреты Blueprint генерирует сам:
   - `DATABASE_URL`: приватная строка подключения Neon;
   - `CLIENT_URL_PROD`: адрес сайта. Для начала можно `http://localhost:3000`, когда клиент работает локально;
   - `ALLOWED_ORIGINS`: адреса разрешённых клиентов через запятую, без завершающего `/`, например `http://localhost:3000`.
5. Команда `start:deploy` проверит конфигурацию, выполнит `prisma migrate deploy`, затем запустит скомпилированный API. Seed автоматически не выполняется и данные не стираются.
6. Проверить `https://<назначенный-домен>.onrender.com/health/detailed`: database и redis должны быть connected. Точный домен назначает Render; не считать имя сервиса гарантией домена.
7. Для локального клиента задать `NEXT_PUBLIC_DEMO_MODE=false`, `NEXT_PUBLIC_USE_DEMO_CATALOG=false`, `NEXT_PUBLIC_API_URL_DEV=https://<домен>/api/v1`, `NEXT_PUBLIC_SOCKET_URL=https://<домен>` и перезапустить Next.js. Для размещённого клиента использовать `NEXT_PUBLIC_API_URL_PROD` при сборке.

## Наполнение и pgAdmin

Не переносить локальную базу целиком в публичную среду: в ней тестовые пароли. Каталог можно создать отдельным запуском seed из локального полного репозитория с DATABASE_URL новой базы и NODE_ENV=production. Перед запуском задать SEED_ADMIN_1_EMAIL/PASSWORD, SEED_ADMIN_2_EMAIL/PASSWORD, SEED_ADMIN_3_EMAIL/PASSWORD. Пароли должны быть уникальными, не стандартными и не короче 12 символов. Production-seed не создаёт стандартного покупателя user123. Повтор seed обновляет цены, остатки и пароли: не запускать при каждом деплое.

В pgAdmin создать **отдельное** подключение GameZone Neon: host/user/database из Neon, порт 5432, SSL mode Require. Локальное GameZone local оставить. Пароль вводить непосредственно в pgAdmin. Выполнить `src/server/scripts/postgres-proof.sql` и сравнить результат изменения цены через админку.

## Границы готовности

Платежи требуют Stripe и webhook secret; письма — SMTP, загрузки — Cloudinary. До настройки соответствующие операции не считаются проверенными. Резервирование остатков и компенсация оплаченного заказа при гонке ещё не реализованы: текущую версию размещать как учебную, без настоящих платежей.

Render Free подходит для учебной демонстрации, а не непрерывно доступного коммерческого магазина. Проверять включённые лимиты в панели; не подключать платные планы автоматически. После перезапуска бесплатного Redis возможен повторный вход. Для размещённого frontend на другом домене ограничения сторонних cookies в браузере могут потребовать общих доменов либо проксирования API; проверить авторизацию в целевых браузерах.
